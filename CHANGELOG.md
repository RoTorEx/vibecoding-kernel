# Changelog

## [Unreleased]


## [1.3.5] - 2026-08-30

### Changed

- Distinguished durable `ROADMAP.md` direction from the accepted executable
  `TASK.md` queue, rejected ambiguous `TODO.md` files, and kept both planning
  files absent from new projects until their separate horizons actually exist.

## [1.3.4] - 2026-08-24

### Changed

- Added a universal outcome-boundary contract that prevents silent scope
  expansion across documented stages, priorities, deferred work, and non-goals.
- Required reference gathering to start with the closest relevant source and
  stop once enough evidence exists for a safe decision.

## [1.3.3] - 2026-08-22

### Changed

- Standardized bulky agent-created scratch, temporary checkouts, build outputs,
  and reusable caches under the disposable `${HOME}/construction_side` root.

## [1.3.2] - 2026-08-22

### Added

- Added a task-owned temporary-artifact lifecycle requiring unique paths,
  attached cleanup, final reconciliation, and explicit reporting for anything
  intentionally retained.

## [1.3.1] - 2026-08-22

### Added

- Added a practical preflight and post-push verification contract for the first
  tag using a new or materially changed automated publishing workflow.

### Fixed

- Made the first `vibe-propose` entry remove the empty-inbox `None.` sentinel.

## [1.3.0] - 2026-08-22

### Added

- Added an explicit maintenance, operation, and audit mode contract so
  repository commits, external workflow execution, and read-only diagnosis no
  longer inherit one another's authority.
- Added an optional agentic-operations recipe for bounded scope, queue
  reconciliation, failure isolation, deterministic mechanics, human
  intervention, and evidence-backed completion.

### Changed

- Limited the commit-and-push task cycle to maintenance work that changes
  tracked repository state.
- Hardened external work by treating retrieved content as data rather than
  instructions and requiring authoritative read-back after sensitive mutation.

## [1.2.1] - 2026-08-22

### Added

- Added a regression check that rejects missing local file and glob references
  routed from the parent `AGENTS.md`.

### Changed

- Moved machine-specific project-manager configuration from public agent rules
  into ignored `AGENTS.local.md`.

## [1.2.0] - 2026-08-22

### Added

- Added an owner-selected Makefile recipe exhibit for local CLI installation
  and the separate interactive release and release-push workflow.
- Added interactive `make vibe-propose` and a managed Makefile command block so
  children can submit structured parent feedback after an ordinary vibe pull
  while preserving all content outside managed markers byte for byte.

### Changed

- Made `make vibe-propose` the only permitted child-to-parent write path and
  documented its pull, permission, submission, and blocked fallback algorithm.

## [1.1.3] - 2026-08-22

### Added

- Added a self-removing first-task brief: new-project agents use an already
  sufficient request or ask one compact question before filling README and
  BUSINESS without inventing rules.

## [1.1.2] - 2026-08-22

### Added

- Made `make new-project` create or adopt an empty target, initialize `main`,
  install the foundation, and create the exact `Initial commit` automatically.

### Changed

- Added the Fiat 500 Abarth design target and a plain-language,
  one-rule-one-canonical-home contract that rejects duplicate rules.
- Clarified that unavailable Make capabilities must be omitted and that product
  details start after the foundational initial commit.
- Documented removal of legacy kernel-managed Git hooks during child adoption.

## [1.1.1] - 2026-08-22

### Changed

- Standardized real releases in the parent and children on the unchanged
  interactive `make release` command, with the version supplied only after its
  prompt so command approval can be reused.

## [1.1.0] - 2026-08-22

### Added

- Added the self-healing evolution contract: local repair, evidence-backed child
  feedback, parent review, versioned release, explicit adoption, and later
  re-evaluation.
- Added a structured parent feedback inbox and rule-quality criteria preserving
  trigger, rationale, evidence, scope, verification, and removal conditions.

### Changed

- Made `vibe-pull` discover every `core/*.md` file so new conditional runtime
  contracts are distributed without sync-code changes.
- Added parent `make release` and `make release-push` implementation.
- Rebuilt the kernel as the incompatible Stage 1 minimum: one required operating
  document, one conditional release contract, versioned explicit sync, a short
  agent router, mandatory local business truth, changelog, and default ignore rules.
- Removed presets, examples, audit prompts, hooks, proposal flow, generated
  context, empty documentation trees, task scaffolding, and specialized runtime rules.
